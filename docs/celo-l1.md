# Celo L1 execution

Celo uses one EVM type. The default remains L2; select historical mainnet L1
execution explicitly:

```sh
leafage-evm standalone --chain-cfg=42220 --evm-type=celo \
  --evm-custom-config='{"execution_mode":"l1"}' \
  --archive --db-path=/path/to/archive
```

L1 accepts block numbers below 31,056,500. The chain ID, fork heights and epoch
size are Celo mainnet's. A fixed `--spec-id`, unknown configuration fields and
unknown execution modes are rejected.

| Fork | First block | Execution changes |
| --- | ---: | --- |
| Initial L1 | 0 | Celo Istanbul gas schedule; no DIFFICULTY or GASLIMIT; precompiles `f4`–`fd` |
| Donut | 6,774,000 | Adds `e1`–`f3` |
| Espresso | 11,838,440 | London opcodes except BASEFEE; Celo CIP-48 gas costs |
| Gingerbread | 21,616,000 | Standard London gas costs, BASEFEE and GASLIMIT; retires `e2`–`f3`; removes Tobin tax |

Addresses in this table are the last byte of a 20-byte zero-prefixed address.

| Addresses | Function |
| --- | --- |
| `fd` | Native-token transfer, authorized through the live Registry |
| `fc` | Fraction multiplication and exponentiation |
| `fb` | BLS12-377 proof of possession |
| `fa`, `f9`, `e1` | Validator address, count and uncompressed BLS public key |
| `f8` | Epoch size |
| `f7`, `f6` | Number and Celo hash of an RLP header |
| `f5`, `f4` | Parent seal bitmap and verified seal bitmap |
| `f3` | ZIP-215 Ed25519 verification |
| `f2`–`ea` | Legacy BLS12-381 arithmetic and mapping |
| `e9`–`e3` | Legacy BLS12-377 arithmetic |
| `e2` | CIP-20 SHA-3, Keccak-512, SHA-512 and parameterized Blake2s |

Validator sets are reconstructed from canonical epoch headers, starting at
genesis, and cached by header hash. The archive must contain those headers.
Missing or malformed archive consensus data is a node error; it cannot turn
into a successful empty validator set or a catchable precompile failure.

Transfer authorization reads Registry state in the current transaction journal.
Before Gingerbread, CALL, CREATE and native-token transfers also execute the
Reserve's Tobin-tax calculation. Its changes and transfers revert with the
enclosing frame. Internal Registry queries preserve the caller's access-list
warmth. The implementation preserves the deployed precompiles' return bytes,
length rules, gas schedule, compressed BLS encoding, GLV arithmetic and legacy
multi-exponentiation window behavior.

One malformed-input behavior is deliberately hardened: a zero denominator in
`fractionMulExp` fails the EVM call. The old Go implementation can panic while
dividing by zero because its zero check compares pointers.

## Transaction blockfiles

An L1 archive with `--rpc-addr=http://127.0.0.1:8665` exposes
`trace_debankBlock`. Leafage reads complete transactions and receipts from
that RPC and executes them against its local parent archive state. It does
not ask the upstream to trace. The source must support
`eth_getBlockByHash(hash, true)` and `eth_getBlockReceipts(hash)`, including
Celo's final system receipt when present. `--trace-block-rpc` is also accepted
as a fallback when `--rpc-addr` is absent.

```json
{"jsonrpc":"2.0","id":1,"method":"trace_debankBlock","params":["0x1d9e273",{"stateDiff":false}]}
```

The response contains `block_file`, `header` and `validation_hash`. Omitting
options also requests only this transaction output. `stateDiff:true` is
rejected: the canonical `state_diff`, which includes consensus finalization
and epoch rewards, must still come from native Celo. Genesis exposes the
Registry's initial storage allocation with empty transaction/trace lists.

Replay verifies the archived Celo header hash, signed transaction encodings,
recovered senders, transaction root, receipt root and log identities. It then
checks every transaction's gas, status and complete receipt logs. A mismatch
fails the RPC instead of returning a partial blockfile. Before transactions,
it applies the block randomness call; fees retain native debit, balance
query, refund and credit ordering. Celo fee-currency and gateway fields are
kept for execution even though the analytical `txs` output omits them.

The trace format follows native Celo's preorder, reverted-event handling,
storage ownership and explicit empty trace for untraced fee logs. In
particular, legacy Celo reports zero value for DELEGATECALL and wraps an
unsigned `gas_used` inside unmetered Registry proxy calls. These historical
trace fields are preserved; they are separate from charged transaction gas.

## Verification

```sh
cargo test -p leafage-evm-chains --lib celo::
cargo test -p leafage-evm celo_selects_mainnet_l2_without_fixed_fork_overrides
cargo test -p leafage-evm-rpc --lib api_impl::celo::trace
cargo test -p leafage-evm-rpc --lib pipeline::
```

The checked-in fixtures are generated by native Celo, including 1014 pure
precompile cases, BLS public-key encodings, 1810 canonical headers and 77
consensus calls. The EVM tests also cover transfer rollback, Tobin tax across
forks, 44 native opcode-gas and system-storage cases, block opcode activation, missing consensus
headers and existing L2 behavior.

`scripts/check_celo_l1_rpc.py` compares an archive-backed candidate with a native
Celo node. It checks historical opcode gas, fork activation, real GoldToken
execution and the native fixtures. Its state overrides only affect individual
`eth_call` requests. Run it on the same machine as the two local RPC endpoints,
using a saved oracle cache to keep repeated native execution bounded.

The development archive run on 2026-10-31 matched all 1,223 cases against
the native Celo oracle: 1,014 pure precompile vectors, 77 consensus calls,
120 historical/live-contract calls across eight fork-boundary heights, and
12 system-storage warm/cold access cases.
The oracle is the independently verified native blockfile implementation in
[celo-blockchain#7](https://github.com/Chaintable/celo-blockchain/pull/7),
commit `f59d067ab`. The Celo test filter passed all 13 tests and the CLI
configuration test passed separately.

`scripts/export_celo_replay_inputs.py` saves immutable, hash-named block and
receipt fixtures from RPC. `scripts/check_celo_l1_trace.py` caches native
reference output, then compares every field of `block_file`, `header` and
`validation_hash`, including array ordering. For example:

```sh
python3 scripts/check_celo_l1_trace.py \
  --oracle http://127.0.0.1:8665 --candidate http://127.0.0.1:8567 \
  --blocks 6773999,6774000,11838439,11838440,21615999,21616000,31056499 \
  --cache /data/celo-reference --output /data/celo-comparison
```

The system-call regression also checks that metered SLOAD/SSTORE accesses
warm the storage owner, including the pre-Espresso, Espresso and Gingerbread
boundaries and rollback. Native system-storage vectors can be added to the
RPC comparison with `--system-storage crates/leafage-evm-chains/testdata/celo_l1/system_storage_gas.json`.

Transaction replay was compared field by field with native Celo at 37 heights:
814 transactions, 18,632 successful traces, 1,629 error traces, 3,082 events
and 91 reverted events. All fields and ordering matched. A separate deterministic
sample of 160 historical blocks replayed 4,498 transactions with all signature,
root, gas, status and receipt-log checks passing. These are transaction-output
checks; consensus finalization and canonical state diffs remain native Celo's
responsibility. The complete RPC crate regression suite passed 156 tests
(two external-service tests were ignored).
