# Cronos mainnet replay

Each height report records the inclusive start of its binary interval, the binary recommended for synchronization, and the effective Ethermint and geth dependencies. The first interval names the v0.6 family. Its dependency pins describe v0.6.1. Later entries use the named release's go.mod, including replacements. The version identifies the synchronization baseline, not the exact patch installed by an individual validator. The replay rule has its own version. Resuming requires both the binary interval and the rule to match the saved report. [Release table](../crates/leafage-evm-rpc/src/pipeline/cronos/releases.rs) · [Mainnet genesis synchronization](https://docs.cronos.com/for-node-hosts/running-nodes/genesis-synchronization)

## Historical execution

- Genesis enables Berlin at block zero and schedules London at 2^63. The ordered extra EIPs are 2929, 2200, 1884 and 1344. The v0.6 keeper uses transient access lists and a refund quotient of two. A reverted transaction can lose its unused-gas refund. [Mainnet genesis](https://github.com/cronos-labs/cronos-mainnet/tree/master/cronosmainnet_25-1) · [Ethermint transition](https://github.com/crypto-org-chain/ethermint/blob/v0.7.2-cronos/x/evm/keeper/state_transition.go)
- At 2,693,800 the v0.7.0 handler runs module migrations, enables the fee market, sets initial base fee to 5,000,000,000,000, elasticity to 2 and the change denominator to 100,000,000, and sets LondonBlock to zero. The keeper uses the London refund quotient and a transaction-local StateDB. [Upgrade handler](https://github.com/crypto-org-chain/cronos/blob/v0.7.0/app/app.go#L708-L728) · [Execution rules](https://github.com/crypto-org-chain/ethermint/blob/v0.10.0-alpha1-cronos-9/x/evm/keeper/state_transition.go)
- At 3,982,500 the v0.8.3 handler runs module migrations. The two pinned versions have identical state_transition.go, EVM StateDB package and fee-market implementation. Keeper account deletion changed. In v0.7 deleting a contract also deletes the bytecode stored under its hash, which another contract can share. v0.8.3 retains that bytecode. Both versions apply the configured extra EIPs to the selected geth jump table. EIP-2929 restores the 24,000 SELFDESTRUCT refund; the London transaction refund cap still applies. [geth EIP table](https://github.com/ethereum/go-ethereum/blob/v1.10.15/core/vm/eips.go#L144-L156) · [Refund implementation](https://github.com/ethereum/go-ethereum/blob/v1.10.15/core/vm/operations_acl.go)
- The v0.8.3 ante handler also changed transaction metadata and event handling. Before v0.8.3, replay reports unsupported committed SELFDESTRUCT state because the earlier keeper lifecycles differ from CacheDB. [Upgrade handler](https://github.com/crypto-org-chain/cronos/blob/v0.8.3/app/app.go#L704-L715) · [Old keeper](https://github.com/crypto-org-chain/ethermint/blob/v0.10.0-alpha1-cronos-9/x/evm/keeper/statedb.go#L176-L210) · [New keeper](https://github.com/crypto-org-chain/ethermint/blob/189ed50c7867/x/evm/keeper/statedb.go#L175-L206)

An upgrade executes after its module migrations and before the first transaction, so its parent still has the preceding release's parameters. The replay also reads the fee-market minimum from the parent, except at Galileo where the migration installs 0.5. An unexpected fork setting, fee-market query failure or unavailable archive state prevents verification. ## Trace gas and Cosmos state

The writer that backfilled heights 1–15,000,000 used Cronos ba3b01be with Ethermint 60189fd0. Its tracer records transaction-end gas on the root. Its reconciliation pass updates that gas from the Comet-backed receipt and copies it into the serialized transaction. Child frames retain the gas measured at frame exit. A historical writer trace can contain a larger root gas limit when its replay retried the transaction with more gas. In the mainnet block at 124,760, reverted transaction `0xbf585b93…` has 810,418 gas on both writer records. Its JSON-RPC receipt has 822,893 gas, equal to the sender's full gas limit under the pre-Huygen refund behavior. Replay checks the Comet gas and receipt gas independently. [Writer transaction assembly](https://github.com/chaintable/ethermint-cronos/blob/60189fd0/rpc/namespaces/ethereum/trace/api.go#L235-L261) · [Receipt reconciliation](https://github.com/chaintable/ethermint-cronos/blob/60189fd0/rpc/namespaces/ethereum/trace/reconcile.go#L95-L125)

A call to the IBC relayer or ICA precompile (`0x65` or `0x66`) needs Cosmos state. A committed log can invoke a registered native hook, including the overloaded IBC event from v1.1.0. The keeper can change bank or IBC state, append logs, or reject the EVM execution. Replay checks the keeper's event signatures for the selected binary, including EVM logs that precede a failed post-transaction hook. Blocks with intervening Cosmos messages or unsupported multi-message ante state also receive a diagnostic. [Precompile registration](https://github.com/crypto-org-chain/cronos/blob/v1.3.0/app/app.go#L592-L604) · [Post-transaction dispatch](https://github.com/crypto-org-chain/cronos/blob/v1.3.0/x/cronos/keeper/evm_hooks.go)

In the supported Prague intervals, the block context leaves BlobBaseFee unset. A BLOBBASEFEE instruction, a failed authorization transaction, or contract creation by a delegated sender therefore requires a separate rule check for the affected behavior. A verified report checks replay gas, transaction status, committed logs and frame relationships. Independent internal call traces can be compared for a sampled transaction. [Prague keeper](https://github.com/crypto-org-chain/ethermint/blob/86f043d7a76a/x/evm/keeper/state_transition.go) · [Pinned geth BLOBBASEFEE](https://github.com/crypto-org-chain/go-ethereum/blob/a4fbafcae0dd/core/vm/eips.go#L289-L294)

A writer frame sets `self_storage_change` when an SSTORE completes and changes the slot value. A later REVERT leaves this frame flag set. A no-op SSTORE or an SSTORE that runs out of gas leaves it clear. Block-level `storage_contracts` has a different definition. It includes addresses with a net committed slot change during any transaction, transaction senders and recipients, and native-denom bank-event addresses.
